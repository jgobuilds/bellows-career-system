# Reconnect List Schema

A living tracking artifact the user keeps and updates. Store it as a Markdown table beside `personal/career-profile.md` (e.g., `personal/reconnect-list.md`), or render it to the Brightside Data brand if the user wants a visual.

## Columns
| Field | Notes |
|-------|-------|
| Name | The person. |
| Now at | Current company + role (best guess is fine; verify on LinkedIn before contacting). |
| From | How you know them (Meridian manager, DataCore peer, hired at X, vendor). |
| Warmth | warm / lukewarm / cold. |
| Usefulness | high / medium / low. |
| Tier | 1–6 from the prioritization rubric. |
| Angle | The genuine reason to reach out / what you share. The seed network turns into a message. |
| Status | not contacted / contacted / replied / conversation had / cold-no-reply. |
| Last touch | Date of last contact, for follow-up timing. |
| Harvest | Names THEY surfaced ("who else?") — these become new step-1 candidates. |

## Status flow
`not contacted → contacted → replied → conversation had`
Branch: `contacted → (no reply ~1wk) → one follow-up → (still nothing) → cold-no-reply` (let it rest; don't pester).

## Health signals to watch
- **Lots of `contacted`, few `replied`** → the *messages* aren't landing. Route back to network and fix the wording/ask, don't just add more names.
- **`conversation had` not producing `Harvest` names** → the user isn't asking "who else should I talk to?" — the single highest-leverage question for a thin network. Prompt them to add it.
- **List stalls / goes untouched** → the tracker became a substitute for sending. The scoreboard is replies and conversations, not rows filled in.

## Keep it honest
Warmth and usefulness reflect reality, not hope. Status reflects what actually happened. A tidy list with no conversations is not progress — it's a signal to change the approach.
